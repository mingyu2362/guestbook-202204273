# 03: 상대 시각 표시

**What to build:** 게시글의 작성 시각이 "방금 전", "N분 전", "N시간 전", "N일 전"처럼 상대 시각으로 표시되고, 7일이 넘으면 한국 시각 기준 날짜로 표시된다. 페이지를 열어 둔 채로 있어도 1분마다 저절로 갱신되며, 마우스를 올리면 한국 시각 기준 전체 시각을 볼 수 있다. "(수정됨)" 표시가 있다면 그 툴팁도 같은 방식으로 동작한다.

명세: [spec.md](../spec.md)의 "상대 시각" 절.

**Blocked by:** 01 (게시글 목록 조회와 페이지 뼈대)

**Status:** ready-for-agent

- [x] 순수 함수 `formatRelativeTime(date, now)`가 있다. 현재 시각을 스스로 읽지 않고, 인자로 받은 두 시각만으로 결과가 정해진다.
- [x] 결과는 다음과 같다. N은 버림으로 계산한다.
  - 1분 미만: "방금 전"
  - 60분 미만: "N분 전"
  - 24시간 미만: "N시간 전"
  - 7일 미만: "N일 전"
  - 그 이상: Asia/Seoul 기준 `YYYY-MM-DD`
- [x] `date`가 `now`보다 미래이면 "방금 전"을 돌려준다.
- [x] 7일 이후의 날짜는 KST 기준이다. UTC 기준으로는 전날이지만 KST 기준으로는 다음 날인 시각도 KST 날짜로 나온다.
- [x] 시각 표시 클라이언트 컴포넌트가 `formatRelativeTime`을 호출하고, 1분마다 `now`를 갱신하며, `title`에 01번의 KST 전체 시각 포맷(`YYYY-MM-DD HH:mm (KST)`)을 붙인다.
- [x] 서버 렌더링과 브라우저 첫 렌더링의 결과가 같아서 hydration 경고가 나지 않는다. 마운트되기 전에는 KST 전체 시각을 표시하고, 마운트된 뒤 상대 시각으로 바꾼다.
- [x] 목록의 작성 시각이 이 컴포넌트로 표시된다. 04번이 먼저 끝났다면 "(수정됨)"의 수정 시각 툴팁도 이 방식으로 맞춘다.
- [ ] 방금 작성한 게시글이 "방금 전"으로 보이고, 1분쯤 뒤 새로 고치지 않아도 "1분 전"으로 바뀌는 것을 확인한다.
- [ ] 브라우저 개발자 도구 콘솔에 hydration 관련 경고가 없다.
