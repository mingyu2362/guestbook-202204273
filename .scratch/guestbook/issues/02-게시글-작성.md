# 02: 게시글 작성

**What to build:** 누구나 이름, 메시지, 게시글 비밀번호를 입력해 게시글을 남길 수 있다. 등록에 성공하면 폼이 비워지고 새 게시글이 목록 맨 위에 나타난다. 입력이 규칙에 맞지 않으면 등록이 거부되고, 해당 입력칸 아래에 이유가 안내되며, 입력하던 값은 유지된다. 게시글 비밀번호는 원문이 아니라 해시로만 저장된다.

명세: [spec.md](../spec.md). 비밀번호 저장 방식: [ADR-0001](../../../docs/adr/0001-게시글-비밀번호-scrypt-해시.md).

**Blocked by:** 01 (게시글 목록 조회와 페이지 뼈대)

**Status:** ready-for-agent

- [ ] 게시글 모듈이 `createPost({ name, message, password })`를 공개하고, `{ ok: true }` 또는 `{ ok: false, reason: "invalid", fieldErrors }`를 돌려준다. 예상하지 못한 DB 오류는 예외로 흘려보낸다.
- [ ] 이름과 메시지는 앞뒤 공백을 제거한 뒤 검증하고 저장한다. 게시글 비밀번호는 공백을 제거하지 않는다.
- [ ] 이름 1–20자, 메시지 1–500자(줄바꿈 허용), 게시글 비밀번호 4–50자를 벗어나면 `invalid`이고, `fieldErrors`에 필드별 안내가 담긴다. 글자 수는 사용자가 보는 문자 단위로 센다.
- [ ] 게시글 비밀번호는 `password_hash`에 `scrypt$<salt hex>$<hash hex>` 형식으로 저장한다. salt는 게시글마다 16바이트를 새로 만들고, hash는 64바이트 scrypt 결과다. `node:crypto`만 쓰고 추가 의존성은 없다.
- [ ] 저장된 해시를 검증하는 함수(`timingSafeEqual` 사용, 형식을 해석할 수 없으면 불일치로 처리)를 게시글 모듈 안에 함께 둔다. 04번과 05번에서 쓴다.
- [ ] 작성 폼에는 이름, 여러 줄 메시지, 가려진 게시글 비밀번호 입력칸과 등록 버튼이 있다. 클라이언트 쪽에는 `required`와 `maxLength`만 두고, 최종 검증은 서버가 한다.
- [ ] 폼은 Server Action으로 제출된다. Server Action은 FormData를 게시글 모듈에 넘기고 결과를 화면 상태로 바꾸기만 한다. 상태는 `useActionState`로 관리한다.
- [ ] 제출 중에는 등록 버튼이 비활성화된다.
- [ ] 성공하면 목록 경로가 재검증되어 새 게시글이 맨 위에 보이고, 폼이 비워진다.
- [ ] 실패하면 필드별 안내가 해당 입력칸 아래에 표시되고, 입력하던 이름과 메시지가 유지된다.
- [ ] 메시지에 `<script>` 같은 HTML을 넣어도 글자 그대로 표시된다.
- [ ] DB를 직접 조회해 `password_hash`에 원문이 아닌 `scrypt$…` 값만 있음을 확인한다.
- [ ] 구현하기 전에 프로젝트에 포함된 Next.js 16 문서에서 Server Actions, `useActionState`, 재검증 API를 확인한다.
