# 04: 게시글 수정

**What to build:** 작성자가 게시글의 [수정] 버튼을 누르면 그 게시글 바로 아래에 인라인 폼이 펼쳐진다. 폼에는 기존 메시지가 채워진 편집란과 게시글 비밀번호 입력칸이 있다. 비밀번호가 맞으면 메시지가 바뀌고, 폼이 닫히고, 게시글에 "(수정됨)"이 작게 표시된다. 목록에서의 위치는 바뀌지 않는다. 비밀번호가 틀리면 수정이 거부되고 그 게시글 아래에 안내가 뜬다. 이미 삭제된 게시글이면 그 사실이 안내되고 목록이 새로 고쳐진다.

명세: [spec.md](../spec.md)의 "수정·삭제 처리 순서" 절. 비밀번호 비교 방식: [ADR-0001](../../../docs/adr/0001-게시글-비밀번호-scrypt-해시.md).

**Blocked by:** 02 (게시글 작성)

**Status:** ready-for-agent

- [x] 게시글 모듈이 `updatePostMessage({ id, message, password })`를 공개하고, `{ ok: true }`, `invalid`(fieldErrors 포함), `wrong-password`, `not-found` 중 하나를 돌려준다.
- [x] 처리 순서는 다음과 같다.
  1. 메시지를 검증한다(trim, 1–500자). 실패하면 DB에 접근하지 않고 `invalid`를 돌려준다.
  2. id로 `password_hash`만 조회한다. 행이 없으면 `not-found`를 돌려준다.
  3. 02번의 검증 함수로 비교한다. 다르면 `wrong-password`를 돌려준다.
  4. 일치하면 `message`와 `updated_at = now()`를 갱신한다. 영향받은 행이 0이면 `not-found`를 돌려준다.
- [x] id가 올바른 정수가 아니면 `not-found`다.
- [x] 이름과 게시글 비밀번호는 수정되지 않는다.
- [x] 각 게시글에 [수정] 버튼이 있다. 누르면 기존 메시지가 채워진 편집란, 게시글 비밀번호 칸, [저장], [취소]가 그 게시글 아래에 펼쳐진다. [취소]를 누르면 아무것도 바뀌지 않은 채 닫힌다.
- [x] 인라인 폼은 게시글마다 독립된 클라이언트 컴포넌트다. Server Action과 `useActionState`로 제출하고, 제출 중에는 버튼이 비활성화된다.
- [x] 성공하면 목록 경로가 재검증되고 인라인 폼이 닫힌다. 바뀐 메시지가 같은 위치에 보인다(정렬은 최초 작성 시각 기준).
- [x] `wrong-password`이면 "비밀번호가 일치하지 않습니다."를 그 게시글 아래에 표시하고, 비밀번호 칸만 비운 채 편집 중이던 메시지는 유지한다.
- [x] `not-found`이면 "이미 삭제되었거나 존재하지 않는 게시글입니다."를 표시하고 목록 경로를 재검증한다.
- [x] `invalid`이면 필드별 안내를 편집란 아래에 표시한다.
- [x] 한 게시글의 안내가 다른 게시글에 표시되지 않는다.
- [x] `updatedAt`이 있는 게시글에는 "(수정됨)"이 작게 표시되고, 툴팁으로 수정 시각이 나온다. 03번이 아직 끝나지 않았다면 01번의 KST 전체 시각 포맷을 쓴다.
- [x] 두 탭을 열고, 한 탭에서 DB로 게시글을 지운 뒤 다른 탭에서 수정하면 `not-found` 안내가 나오는 것을 확인한다.
